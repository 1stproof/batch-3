# Offline probe runtimes

Offline Python and Lean probes execute model-supplied source inside a kernel boundary. Output is bounded evidence, never a proof grade. The host retains exact source and result receipts. Missing enforcement returns `unavailable`; there is no unsandboxed retry.

On macOS the runtime uses `sandbox-exec`, Apple's Command Line Tools Python, and the configured prebuilt Lean executable/libraries. On Linux it requires a native aarch64 or x86_64 runtime, Landlock ABI 3 or later, and `libseccomp.so.2`. Linux Python is the distribution's `/usr/bin/python3` with its system standard library, invoked with `-I -S -B`; this does not expose a host scientific virtual environment. Lean uses the exact configured executable and narrow public prebuilt library roots. Runtime installations and public libraries are trusted host inputs.

Linux confinement is installed in the child before exec. The host must have exactly one OS thread; the dedicated probe CLI satisfies this requirement. A multithreaded library caller is refused. The child inherits no provider credentials or caller environment and no extra file descriptors. Landlock permits read-only runtime libraries and the exact Lean input. All filesystem writes are denied. Seccomp permits bounded runtime operations, denies networking and process escape, and permits only the exact pthread clone flags required by Lean. Resource-limit updates apply only to the child itself. Filesystem existence/stat metadata is not fully hidden by Landlock; private file contents are not granted.

The host enforces CPU/wall time and combined output limits and kills its owned process group on overflow or timeout. Lean threads share the process and cannot create separate processes through the allowed clone rule. The CLI shares its caller-owned helper group for cancellation. There is no claim of a hard memory/RSS limit beyond limits independently supplied by the container or host.

A Docker image must include a supported system Python, libseccomp, Lean and its precompiled public dependencies. Ordinary Docker execution needs no privileged mode, extra capabilities, daemon socket, or unprivileged user namespaces. Kernel support must be checked by real positive and denial tests on the deployment architecture; cross-architecture emulation is not certified by native-architecture tests. A Linux installation with disabled Landlock or blocked policy syscalls fails closed.
