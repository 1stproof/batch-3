# Continuing unfinished pilot research

A no-action mathematical checkpoint is progress bookkeeping. It does not close an
unfinished authorized research goal. The original Astra main continues under a
host-recorded research strategy: obstruction analysis, alternative representation,
discriminating research, or assumption and strategy reassessment. The prompt asks
for actual attempted development, not a plan to work later. Strategy turns retain
the original session and are accounted as `scientific_strategy_development`.

The controller records each strategy transition with exact candidate, findings,
execution and route-history hashes. A compact current state links immutable prior
transition receipts. Latest substantive review, scope, Silver and controller
feedback remains supplied without recursively nesting earlier scheduling prompts.
Optional typed `research_work` documents actual attempted analysis separately from
the full candidate. Neither its text, a strategy counter nor a changed mode proves
progress or renews a paid review or route portfolio. Unchanged assessments remain
deduplicated; new mathematical work must meet the existing evidence and task gates.

Already accepted peers are not restarted. Continuation preparation validates their
unchanged manifests and acceptance evidence through the new controller and records
exact carry-forward bindings. Startup checks current controller validation again
before skipping all main, worker and review dispatch for those completed peers.
A stale or unsuccessful result cannot be carried as complete.

Explicit user interruption, cooperative drain, subscription quota failure,
infrastructure or invalid-protocol failures, and bounded-call hang protections
still stop the applicable work honestly. No overall time budget or new lifetime
review-attempt cap is introduced. No checkpoint, strategy transition or carried
historical claim bypasses current proof, independent scope, Silver or campaign
acceptance requirements.

## Explicit operational handoff

An ordinary no-action checkpoint still continues research. A separate voluntary
`operational_handoff` is available only when the host supplies an eligible current
candidate and authenticated exhausted-review IDs. Its exact five-field response is:

```json
{
  "response_type": "operational_handoff",
  "selected_candidate_sha256": "<exact current host hash>",
  "exhaustion_ids": ["<all matching host IDs>"],
  "reason": "<nonempty operational explanation>",
  "no_new_scientific_work": true
}
```

The last field is the main's self-report, not a mathematical verdict or proof that
all useful work is exhausted. New scientific changes or findings must be submitted
through their existing contracts; never conceal them or make cosmetic edits to
obtain review eligibility. A pending draft cannot use this channel. The host checks
the exact submitted document, current candidate, original main's completed verified
response and the consumed review pair. It preserves the candidate, proposals,
findings and history without publication or new acceptance. No unchanged-step
threshold triggers this outcome.

The problem ends **partial / supervisor needed**, with a durable receipt. It does
not trigger an exam paper job. Direct call entry points refuse a pending handoff.
A completed transport handoff answer can be recognized after a crash even before
the campaign response copy or receipt was written; malformed or stale state fails
closed. The ordinary continuation loader refuses either a pending receipt or an
unrejected completed handoff response, before constructing a successor. This
upgrade provides no automatic acknowledgement or reentry mechanism. A later
explicit supervised resolution requires a separately authorized operation; copying
files to a new root does not reset the barrier.

A previously stopped run without a handoff can resume under its usual independent
lifecycle gates so the same original main can make an informed decision under this
contract. It may then hand off immediately. This supplies a safe operational exit,
not the missing independent verdict, scientific progress, or a useful-restart
guarantee. All prior review limits, exhausted reviewers, model choices, original
scope and acceptance gates remain unchanged.


## Explicit operational recovery and requested alternatives

A saved operational handoff is a request for supervisor attention, not mathematical rejection.
An operator may explicitly pass `operational_handoff_resolution=Path(...)` to
`prepare_continuation`, or `--operational-handoff-resolution FILE` with a reconciled
CLI continuation. The CLI's normal continuation command also runs the successor;
use the Python preparation API when a separate prelaunch audit is required.
The request must be outside both research roots and bind the exact sealed parent manifest,
problem, original main session, saved handoff hash and stage/answer, candidate, submitted
proof revision/hashes, matching exhaustion IDs, fixed successor, and hashed external
user-authorization evidence. See `pilot_handoff_resolution.FIELDS` for the exact schema.
The operator is responsible for authenticating user permission before supplying the path;
the runtime validates its evidence binding, not the truth of arbitrary authorization prose.
Main responses and campaign files cannot issue resolutions.

The old handoff and failed-review history remain unchanged. Hash-bound continuation
provenance preserves the explicit resolution through later successors, without issuing
another resolution or changing its original target. The existing exclusive continuation
reservation prevents competing preparations. A partial preparation requires supervision;
a missing, changed or ambiguous binding does not permit dispatch. A later valid handoff
gets a separate immutable receipt and stops again. Resolution does not grant fresh review,
raise timeouts, reset counters, change models/offline capability, or award acceptance.

When parallel routes are enabled **and explicitly user-requested**, the original main may
use the existing actionable `blocked_checkpoint.proposed_work.route_scout_tasks` to nominate
two to four distinct `scientific_alternative` questions on valid current ledger rows,
within the saved host width. Fresh campaigns enable this advisory option with width four;
main chooses the smallest useful portfolio, or no scouts at all. Saved explicit widths
remain unchanged, and a missing legacy configuration remains disabled with width two.
Empty obstruction IDs are permitted in this case: this is user-requested advisory exploration,
not a finding that the proof has a gap. Fabricated finding IDs remain invalid.
General authorization to explore does not override convergence: unrelated routes pause once
a promising skeleton exists, while necessary current-gap work remains eligible. This replaces
the older user-requested convergence bypass in the maintained runtime; frozen runs are unchanged.
Certificate-strategy requirements remain unchanged. The stable candidate/evidence census,
distinct fresh advisory actors, preserved failed/partial slots and original-main synthesis
remain required; changing task wording or target selectors does not purchase another user-only
portfolio. Exploration is optional, never an automatic response to every operational blocker.

If scout results lead to genuinely changed original-main scientific content, existing review
admission applies. **Scout-only evidence with unchanged proof does not renew an exhausted review.**
This limitation is deliberate in this repair; a separate bounded fresh-review policy would need
its own authorization and independent audit. Restored choices do not guarantee mathematical
progress or improved performance.

### Stable execution identity and completed-assessment attention

Dispatch deduplication uses versioned producer identities shared by live execution
and native continuation. A worker atom binds its dispatch name, request, answer
hash, session, and parsed output; a probe atom binds its confined producer path,
source bytes, and result. Grouping, root relocation, repeated presentation, and
unadmitted/deferred work cannot renew a review. Conflicting content for one
producer fails closed. Actual failed diagnostics remain evidence; another real
producer remains distinct even when output is identical.

New assessment and checkpoint records carry execution identity version 2.
Historical keys and consumed admissions are never rewritten. An applicable legacy
record without enough canonical identity requires operational reconciliation,
rather than granting a new review after a format change. Authenticated unrelated
scientific candidates remain eligible through ordinary gates. This is a conservative
compatibility boundary, not automatic migration of every historical reservation.

A main at an authenticated completed `INCOMPLETE` assessment may still repair its
proof, propose genuinely new lawful work, or supply required independent evidence.
If it explicitly reports no concrete new scientific work, the host offers the
separate `assessment_handoff` response with exact current candidate and assessment
IDs. A valid request saves an immutable attention receipt and leaves that problem
partial for supervisor diagnosis. It is voluntary, never a count-based research
cutoff, and does not declare any finding false, grant acceptance, renew review,
reset a budget, or stop another problem. Fresh reviewer identity and complete
required delivery are prerequisites. An unresolved receipt, or authenticated
handoff answer saved before receipt publication, prevents automatic continuation.
There is no automatic resolution API for this new boundary: supervisor diagnosis
is required before any separately authorized recovery implementation.
